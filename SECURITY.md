# Security Policy

## Supported versions

Security fixes are developed against the latest maintained release. Until a first tagged release exists, use the current default branch for fixes and testing.

## Report a vulnerability privately

Use GitHub's private vulnerability reporting form on the repository Security tab. [Open a private report](https://github.com/Waffing/codex-deck/security/advisories/new).

Include the affected version or commit, deployment mode, prerequisites, expected and actual behavior, impact, and a minimal reproduction with synthetic or redacted data. Keep credentials, session cookies, signed links, affected user data, and vulnerability details out of public issues, pull requests, and discussions.

If the private reporting form is unavailable, look for a private contact method on the maintainer's profile. [Waffing](https://github.com/Waffing).

## Response and disclosure

Maintainers triage reports in the private channel, coordinate mitigation and disclosure with the reporter, and publish an advisory once a fix or mitigation is available. Please keep report details private while the team investigates.
